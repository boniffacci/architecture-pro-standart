### <a name="_3bfxc9a45514"></a>**Функциональные требования**  

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
| 1 | Оператор внутреннего кол-центра | Получение ставок через API | Оператор в интерфейсе кол-центра видит актуальные депозитные ставки, получаемые из АБС по API. |
| 2 | Оператор партнёрского кол-центра | Получение ставок из файла | Оператор видит ставки, загружаемые в систему партнёра из файла, предоставленного банком. |
| 3 | АБС (сервис депозитов) | Формирование файлов ставок | Сервис автоматически формирует файл (CSV/JSON) с актуальными ставками. |
| 4 | Система банка | Передача файла ставок партнёру | Система выгружает файл ставок и отправляет его на SFTP-площадку партнёрского кол-центра. |
| 5 | Маркетинг/кол-центр | Снижение нагрузки | Возможность распределить обращения между внутренним и партнёрским кол-центрами. |

### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**  

|**№**|**Требование**|
| :-: | :- |
| 1 | Обновление ставок минимум раз в сутки, желательно каждый час |
| 2 | Шифрование каналов передачи (SFTP, TLS для API) |
| 3 | Контроль успешной выгрузки и доставки файлов |
| 4 | Удобство интеграции для партнёра (поддержка стандартных форматов CSV/JSON) |
| 5 | Масштабируемость: возможность подключить несколько партнёрских кол-центров |

**Описание основных компонентов:**  
- **АБС (сервис депозитов)** — источник актуальных ставок.  
- **API депозитов** — предоставляет ставки внутреннему кол-центру.  
- **Модуль выгрузки ставок** — формирует файлы ставок в CSV/JSON.  
- **SFTP-шлюз** — отвечает за доставку файлов партнёрскому кол-центру.  
- **Система внутреннего кол-центра** — получает данные ставок по API.  
- **Система партнёрского кол-центра** — получает ставки из файлов, загружаемых по SFTP.  

**Логика выбора решения:**  
- Внутренний кол-центр работает в онлайне, поэтому выбрано API.  
- Партнёрский кол-центр ограничен по технологиям и готов только к приёму файлов → выбран SFTP.  
- Комбинированный подход позволяет покрыть оба сценария и снизить риски перегрузки.  

---

### <a name="_bjrr7veeh80c"></a>**Альтернативы**  

1. **API-only**  
   + Онлайн-доступ, минимальные задержки.  
   – Неприемлемо для партнёра (нет API).  

2. **Только файлы**  
   + Универсально, легко для партнёров.  
   – Ухудшение опыта внутренних операторов (нет онлайн-данных).  

3. **Комбинированный подход (API + файлы)**
   + Покрывает оба сценария.  
   – Увеличение сложности архитектуры (два канала передачи).  

---

**Недостатки, ограничения, риски**  

- Увеличение операционных расходов (поддержка двух каналов интеграции).  
- Риск несвоевременной доставки файлов партнёру (падение SFTP).  
- Необходимость мониторинга и алертинга по выгрузкам.  
- Для пожилых клиентов остаётся риск увеличенной нагрузки на кол-центры, требуется параллельная работа по улучшению UX интернет-банка.
